# 司凤转发 · 故障排查

返回 [安装与使用](../README.md)。先看暂停原因，再查看“好友读取诊断”和运行记录。截图或复制报告前，检查是否包含账号、好友、视频、邮箱等个人信息；不要附 `.env`、cookie 或授权码。

## 按现象定位

| 现象 | 优先检查 | 下一步 |
| --- | --- | --- |
| 加载扩展提示找不到 manifest | 是否仍在 ZIP 中、选错了目录 | 解压，选择直接包含 `manifest.json` 的 `extension/` |
| `python` 不存在或打开 Microsoft Store | Python 是否已安装并可从终端找到 | `python --version`；也可尝试 `py -3 --version`，之后使用 `py -3 -m runner.mail_bridge` |
| 无法运行 `start-mail.ps1` | PowerShell 脚本策略 | 在项目根目录直接执行 `python -m runner.mail_bridge`，不必修改全局策略 |
| `Failed to fetch`／无法连接本地邮件服务 | 本地 Python 服务是否运行、端口是否 17321 | 重新启动服务，保持窗口开启，再点“检查邮件服务” |
| 连接令牌不匹配／401 | 插件令牌和 `.env` 是否完全一致 | 核对 `BOT_BRIDGE_TOKEN`，保存插件设置；改 `.env` 后重启邮件服务 |
| 服务配置不完整 | SMTP 主机、发件人、收件人、授权码是否填全 | 按邮箱服务说明填写 `.env`，不要使用模板占位文字 |
| 连接检查通过但没收到邮件 | 检查不登录 SMTP，也不验证收件 | 主动点“发送测试邮件”，看服务窗口错误与垃圾邮件；核对授权码、端口和 TLS 配对 |
| 端口被占用 | 是否已经启动了另一个邮件服务 | 先在插件检查现有服务；不要重复启动或随意结束未知进程 |
| 无法识别账号／账号不一致 | 是否同一浏览器配置、是否已登录、是否切换了账号 | 手动确认登录后重新绑定正确账号，不要直接改存储中的账号 ID |
| 找不到分享入口／好友转发按钮 | 是否打开了具体可分享视频，工作页是否加载完成 | 当前待发好友会在发送前最多刷新两次，共三次页面尝试；仍失败才暂停告警，复制最新诊断 |
| UID 控件 0 个／好友面板为空 | 面板是否实际展开、工作窗口是否被最小化或回收 | 手动打开一条视频，点“诊断分享面板”；保留工作窗口，处理睡眠标签页设置 |
| 好友读取有遗漏 | 首屏、累计未识别、停止位置和跳过原因 | 重新读取并复制完整诊断，不要按昵称强行替换 UID |
| 调试接口不可用 | 开发者工具或其它调试器是否占用工作标签 | 关闭该标签的开发者工具后重试；企业浏览器策略也可能禁止此权限 |
| 原生“最新发布”筛选未识别 | 页面是否已登录、筛选工具栏是否出现、窗口布局是否改变 | 手动刷新并检查可见布局，再点“试检索，不发送”；仅改变显示器不一定是根因 |
| `target_closed`／调试会话断开 | 工作标签关闭、导航、睡眠或浏览器回收 | 保留独立工作窗口，并设不休眠例外；已点击后的中断要人工核对 |
| 验证码／安全验证／操作频繁 | 平台风控提示 | 由本人完成验证并调整使用节奏，解决后恢复；程序不会替你绕过 |
| 已收到但仍提示发送结果不明 | 页面成功提示可能未被捕获 | 先看聊天记录，确认收到后标记已发送；不要点“确认未发送，重试” |
| 旧版提示“本轮查询过多，超出单轮任务预算” | 是否已重新加载到新版 | 新版保存查询进度，先发已有队列，发完自动继续；预算不足本身不再暂停告警 |
| 发了一部分后遇到限速 | 核对版本是否为 20 | 新版显示“等待限速”，保持运行并自动续发，不用再次点击；若仍显示已暂停，检查手动暂停或具体错误报告 |
| 等待限速／自动续发 | 查看预计继续时间与运行模式 | 保持浏览器和邮件服务运行；待发直发只续发，全自动发完后再抓取；不要为了提速清空防重或限速记录 |
| 点“发送待发视频”不可用 | 是否仍在监控／忙碌，是否有 unknown | 先暂停并等待本轮结束，人工处理待核对记录 |
| 没有可发送的待发视频 | 已发过、已跳过、上轮缓存已过期或规则不再匹配 | 查看队列、窗口和运行记录，需要时重新试检索 |
| 监控中但没有继续发 | 限速、轮次时限、没有新命中或已去重 | 查看不同视频限额、待发数、检索日志和下轮检查，不要通过删除记录强行重发 |

## 诊断一直显示旧结果

1. 等当前操作结束。打开 `edge://extensions` 或 `chrome://extensions`，点扩展的“重新加载”。
2. 刷新**插件设置页**。顶部应显示当前后台版本 `0.2.1（邮件可选与暂停修复）`。
3. 点“诊断分享面板”或重新执行需要检查的动作，确认报告时间、类型、状态已改变。
4. 报告中“报告版本”代表那条记录生成时的版本；“当前后台”才是现在运行的版本。历史报告未记录版本不代表当前后台一定旧。
5. 若仍不更新，附当前后台版本、报告时间及最新错误。不要仅反复刷新抖音网页。

新版本按递增序号保存运行开始、结束与失败报告；启动邮件检查失败及没有可用标签页也应生成新报告。

## 视频不存在、被删除或下架

版本 21 在发送前识别“你要观看的视频不存在”等明确提示，跳过同一视频剩余好友并继续队列，不告警。列表显示“失效跳过 X 项”，诊断汇总本轮跳过数量，运行记录保留视频 ID 和原因；历史成功记录保留，跳过不算发送成功。失效标记按账号保存，搜索再次命中也不重复入队。

若仍卡住，先重新加载扩展，刷新设置页，确认当前后台为 `0.2.1（邮件可选与暂停修复）`。没有明确失效提示、加载失败或提示文字变更时，插件不会猜测并删除任务；提供页面具体提示即可，不需要账号、好友或视频链接。已点击后的未知发送仍需核对，不能用“后来视频失效”认定未发。

## 发送不确定时，先核对再恢复

“发送结果无法确认”可能发生在真正发送之后。请进入目标好友聊天记录核对具体视频，不以“面板关闭”或“没有看到提示”代替结论。

- 确认已收到：选择“核对后标记已发送”。
- 确认未收到且要重发：选择“确认未发送，重试”。
- 不再发送：选择“跳过这位好友”。

人工处理后还需要点击恢复或待发直发。任何 AI 都不应根据模糊截图自动替你作出这些结论。

## 提交一个可排查的问题

从仓库 Issues 选择“问题反馈”，提供：

1. 系统、浏览器版本、插件顶部显示的后台版本。
2. 操作的是“读取好友”“试检索”“待发直发”还是“开始监控”。
3. 可重复的步骤；出错在本轮第一位还是后续好友、同一视频还是下一条视频。
4. 最新诊断文字／脱敏截图，尤其是视口、首屏／累计数量、错误代码、时间和状态。
5. 是否实际收到卡片。只在本人已核对时填写已收到／未收到，否则填写“尚未核对”。

不必公开真实好友昵称、UID、头像、聊天内容或视频链接；若最小匿名页面结构足以复现，优先提供匿名结构。

## 本轮数字与结果

“本轮已发送卡片”从每轮完整检索／试检索／待发直发开始计数；自动分段查询、续发和限速等待共用本轮，不清零。暂停或结束后保留，新一轮重新从 0 开始；刷新设置页不算新一轮。旧发送记录保留用于去重，不删除。页面在发送前已经显示已发的对象，也不算本轮新发送。

“本轮发现”会显示开始时间和查询进度。零结果会明确显示；查询失败保留已找到的部分结果；待发直发和同视频续发显示本次待发清单，并注明不重新查询。若仍是旧统计，先暂停，重新加载扩展并刷新设置页，核对顶部为 `0.2.1（邮件可选与暂停修复）`。


## 全自动与等待状态

“全自动循环”会反复抓取、发完本批、再抓取；没有新待发内容时按检查间隔等待。发送限速是正常等待，不是报错。任务保持运行，预计时间是浏览器的计划唤醒时间，可能略晚。不要为提速清空 rate 或发送记录。

“发送待发视频”也会自动等待并续发，但全部发完后停止，不查询新内容。若不想继续，点击暂停即可取消后续唤醒。验证码、账号不一致或发送回执不明仍按真实错误处理；核对后再手动恢复。

## 找不到功能或按钮说明

每块区域右上角的圆圈问号可悬停查看；移进说明浮窗可滚动，移开后隐藏。Tab可聚焦问号，Esc关闭；触屏可点问号，点空白关闭。若没有问号，请先暂停任务，在扩展管理页重新加载，再刷新设置页，确认后台为 `0.2.1（邮件可选与暂停修复）`。仅刷新抖音页不会更新旧扩展。

## 工作窗口小、视频播放有声音

版本23会在新建或复用抓取／分享窗口时自动最大化并静音。新窗口先打开空白页，静音确认后才加载抖音；同视频续发不刷新。只静音工作标签页，不改变其他浏览器标签或系统音量。若仍是小窗口或有声，暂停任务，重新加载扩展并刷新设置页，核对后台为 `0.2.1（邮件可选与暂停修复）`，再启动。若浏览器拒绝最大化或静音，任务会说明原因并停止，不继续发送。

## 手动暂停或不想配置邮箱

手动暂停在点击发送前发生时正常取消，不发送告警，待发队列保留。已经可能发送但回执不明的记录仍需人工核对；旧邮件和真实事故不因暂停消失。

不需要邮件时，取消勾选“启用邮件告警”并点击“保存规则与设置”，即可不启动本地邮件服务直接使用插件。新安装默认关闭；旧版有令牌时保留开启状态。关闭后仍有页面错误提示和暂停，但没有连接检查、邮件发送或重试。
