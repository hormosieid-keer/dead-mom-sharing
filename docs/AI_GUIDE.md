# 司凤转发 · AI 操作指南

面向帮助用户安装、使用或维护“司凤转发（dead-mom sharing)”的 AI。项目主题是抖音司凤视频一键转发，匹配范围由用户填写的话题和文案关键词决定；“一键”指完成配置后启动已有队列／缓存的转发流程。先读 [README](../README.md)、[AGENTS.md](../AGENTS.md) 与 [验证边界](../TESTING.md)。本指南描述软件流程，不代替用户授权真实发送。

## 先确认任务属于哪类

| 用户目的 | 可以先做的工作 | 必须区分的实际动作 |
| --- | --- | --- |
| 安装 | 检查解压目录、Python、浏览器、扩展清单；准备配置说明 | 登录、绑定和读取页面可能需要用户参与；不能索要 cookie 或密码 |
| 配置邮件 | 说明字段、核对服务存在与健康状态 | 不输出 `.env`；连接检查不等于真实发信，发测试邮件需要用户授权 |
| 测试匹配 | 读取规则、执行用户授权的“试检索，不发送” | 不应顺便按“开始监控”或待发直发 |
| 转发视频 | 明确目标账号、规则、接收人和范围，检查 unknown | START、AUTO_LOOP 与 SEND_PENDING 都可能立即对外发卡片 |
| 排查不明发送 | 收集最新脱敏报告与用户核对结论 | 只有本人明确确认收到／未收到后，才能对应处理记录 |
| 改代码 | 匿名复现、离线测试、打包、说明重载 | 不为验证补丁自动发真实卡片或邮件 |

已有明确授权时按授权范围执行，不要重复索要同一许可；缺少凭证时让用户在本机填写，不要求粘贴到聊天。

## 安装顺序与完成条件

1. **确认是否使用邮件**：关闭邮件告警时仅需 `extension/manifest.json`，不要求 Python、`.env` 或邮件服务。启用邮件时再准备完整包中的 `runner/mail_bridge.py` 和 `.env.example`，下面2、3、5、6步仅对此情况适用。
2. **检查 Python**：`python --version` 或 `py -3 --version`，要求至少 3.10。邮件桥接不需要 pip 安装 Playwright。
3. **处理 .env**：仅在不存在时从 `.env.example` 创建。已有文件保留；不读取并打印真实值。让用户私下填写 SMTP 和随机 32+ 字符 token。
4. **加载扩展**：引导用户到浏览器扩展页加载 `extension/`，核对实际后台版本。用可用 UI 工具时优先定位可见控件，不猜坐标。
5. **启动邮件服务**：项目根目录 `python -m runner.mail_bridge`。已有实例时先做只读检查，不结束未知进程或改变端口。
6. **连接令牌**：启用邮件告警后，用户在扩展填同一 token 并保存；MAIL_HEALTH 可检查，不发送邮件。关闭时不检查、不发送、不重试。实际 SMTP 投递需用户主动测试或明确授权。
7. **登录和账号**：用户在同一浏览器配置登录，绑定并核对账号。验证题交由本人完成。
8. **读取好友**：先开具体视频，再 FRIENDS；检查首屏／累计与跳过原因。在目标规则中选择接收人，不凭昵称构造 UID。
9. **试检索**：保存设置并 SCAN，核对结果、时间窗口和接收规则。
10. **真实发送**：仅在授权范围内执行 START、AUTO_LOOP 或 SEND_PENDING。有 unknown 先停下让用户核对，不通过改存储“修好”状态。

安装完成应说明：运行的是哪个版本、邮件连接是否仅通过配置检查还是已实际收件、是否只做试检索、是否真的转发过。不要把“代码已写好”“离线测试通过”说成真实平台端到端通过。

## 最小只读检查

在项目根目录，以下命令不打印凭证：

```powershell
python --version
Test-Path -LiteralPath extension\manifest.json
Test-Path -LiteralPath runner\mail_bridge.py
Test-Path -LiteralPath .env
Invoke-RestMethod http://127.0.0.1:17321/health
```

最后一项需要服务已经运行，只会返回配置状态。不要把 token 放到会被共享的命令行、日志或截图。授权的浏览器工具可能提供只读 STATUS；扩展消息只能从本扩展页面调用，普通网页不能直接调用后台。

## 快速诊断顺序

1. 先确认启动按钮：版本 21 中 SEND_PENDING 会自动等限速并续发，全部发完才停，始终不查询；AUTO_LOOP 抓取后发完本批再抓取，直到暂停或报错。resumePlan 是正常等待计划，不能误判为故障；不要重复启动或擅自扩大真实发送范围。
2. 当前后台 build → 报告时间、序号、类型、状态 → 本轮第一条还是中途 → 点击发送之前还是之后。
3. 邮件连接问题先检查服务／令牌；登录或验证码交由本人；不把所有失败解释成浏览器焦点问题。
4. 当前待发好友在发送前缺少分享入口／好友行／转发按钮时，最多刷新当前视频两次，共三次页面尝试；适用于中途好友。保留同一视频、UID、发送预留和轮次，不能重发已确认的好友；三次均失败才暂停告警。验证码、账号变化、歧义和可能已发送不进入刷新分支。
5. 查询预算不足是正常分段事件：检查 searchCheckpoint 的 nextIndex／phase 与本轮阶段，先发完 pending，再由续段闹钟继续查询；不要标为故障或清空发送记录。试检索的 scanCheckpoint 仅由下次 SCAN 续查，SEND_PENDING 不续查查询，只续发待发队列。
6. 版本21在点击前明确识别“你要观看的视频不存在”等失效提示时，跳过同视频剩余 pending，继续队列，不发告警。按账号保存 unavailableVideos 防止再次入队，已发与不明记录不可改成跳过；验证码、账号变化、网络错误不能冒充失效。
7. 已点击后的错误按未知结果处理。查看用户实际收件结论，不推断“没有提示”等于“未发送”。
8. 复制诊断优先于原始 DOM／整段聊天内容；如确需页面结构，先脱敏并只取必要范围。

详细故障表见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md)。

## 接手代码

先阅读 `core.js` 状态转换，再看 `background.js` 调度与 `adapter.js` 页面边界。独立指针负责真实输入，options 负责 UI；邮件服务不应接收浏览器传来的任意收件人。

```sh
npm ci
npm test
python -m unittest discover -s tests -p "test_*.py" -v
npm run docs:check
```

针对故障选择匿名 fixture，不写只复制实现的无意义测试。涉及实际页面刷新／输入时可用独立 Chromium 联调，不能复用日常浏览器用户目录。完整模拟联调占用 17321，已有真实服务时改用随机端口的独立测试，不擅自停服务。

改完扩展后：**提醒重新加载扩展，再刷新设置页核对版本**。单纯刷新抖音页不够。若不能代用户完成重载，清楚列出这个剩余步骤，不声称已在真实 Edge 运行了新代码。

本地未公开的历史交接文档不是公开安装依赖；使用当前 README、代码、测试与本文即可接手。发布时只运行公开文件清单，不打包用户机器的整个目录。

## 界面说明入口

版本22在每块区域右上角提供圆圈问号，悬停查看本区用途和各按钮说明；动态规则卡片及好友诊断框也有。说明可滚动，离开后隐藏，支持键盘聚焦与Esc关闭，触屏点问号查看。帮助内容纯本地，不启动、保存或发送。指导用户时可先让其查看对应问号；解释真实发送、测试邮件和导入替换范围时仍以实际按钮行为为准。

## 后台最大化与静音

版本23会自动把抓取／分享使用的独立窗口在后台最大化，将工作标签页静音；新窗口先打开空白页，静音确认后才导航。复用和同视频续发也检查，不修改其他浏览器标签或系统音量。不要用聚焦窗口或逐人刷新代替此流程。最大化／静音失败时根据报告处理，不能跳过检查继续发。
